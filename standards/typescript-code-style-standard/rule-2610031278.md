# The Rosinfotech Base Standards

## The TypeScript Code Style Standard

### Imports

#### Rule #2610031278

* Context:

  * A type-only import and a runtime import have different lifecycles - the type one is erased at compilation; mixing them hides which imports carry runtime weight;

* Description:

  * Type-only imports use the separate `import type { ... } from "..."` statement - not the inline `import { type X }` specifiers (`@typescript-eslint/consistent-type-imports` with `fixStyle: separate-type-imports`);

  * The type import group opens the import block (see [Rule #2610031258](/standards/common-code-style-standard/rule-2610031258.md));

  * Enforcement - the rule is supported by the repository [eslint-config-typescript](https://github.com/rosinfotech/eslint-config-typescript);

* Benefits:

  * The runtime dependency list stays clean - erased imports are visible as such;

  * Faster compilation and smaller bundles;

  * One canonical form of type importing.

* Examples:

  * Case #1:

    * Incorrect:

      ```typescript
      import { type IUser, UserService } from "./user";
      ```

    * Correct:

      ```typescript
      import type { IUser } from "./user";
      import { UserService } from "./user";
      ```
