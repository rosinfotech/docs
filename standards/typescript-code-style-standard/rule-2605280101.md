# The Rosinfotech Base Standards
## The TypeScript Code Style Standard

### Types

#### Rule #2605280101

* Description:

  * Type constructs must use a prefixed naming convention:

    * Interfaces — prefixed with `I`;
    * Type aliases — prefixed with `T`;
    * Enums — prefixed with `E`;
    * Type parameters (generics) — prefixed with `G`;

  * ESLint rule: `@typescript-eslint/naming-convention`;

* Benefits:

  * Readability — type kind is immediately visible from the name;
  * Searchability — easy to find all interfaces, types, enums, or generics by prefix;
  * Uniformity — consistent naming across the entire codebase;

* Examples:

  * Case #1:

    * Incorrect:

      ```typescript
      interface User { name: string; }
      type Status = 'active' | 'inactive';
      enum Direction { Up, Down }
      function get<GItem>( items: GItem[] ): GItem | undefined { … }
      ```

    * Correct:

      ```typescript
      interface IUser { name: string; }
      type TStatus = "active" | "inactive";
      enum EDirection { Up, Down }
      function get<GItem>( items: GItem[] ): GItem | undefined { … }
      ```
