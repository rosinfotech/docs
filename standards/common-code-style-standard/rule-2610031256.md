# The Rosinfotech Base Standards

## The Common Code Style Standard

### Sorting

#### Rule #2610031256

* Context:

  * Unsorted collections (object literals, interfaces, type shapes, JSX props) cost search time and produce noisy diffs on insert;

* Description:

  * Comparable collections are sorted alphabetically, ascending, case-sensitive (`perfectionist/sort-objects`, `perfectionist/sort-interfaces`, `perfectionist/sort-object-types`, `perfectionist/sort-jsx-props`: `alphabetical`, `asc`, `ignoreCase: false`);

  * Partitions: a comment line or an empty line starts an independent sort group - sorting never crosses a partition (`partitionByComment: true`, `partitionByNewLine: true`);

  * The companion of the naming sequence [Rule #2103052001](/standards/common-code-style-standard/rule-2103052001.md): sorted names keep related items grouped in listings;

  * Enforcement - the rule is supported by the repositories [eslint-config-javascript](https://github.com/rosinfotech/eslint-config-javascript) and [eslint-config-react](https://github.com/rosinfotech/eslint-config-react);

* Benefits:

  * Searchability - an item is found by its alphabetical position;

  * Stable diffs - an insertion does not reshuffle the collection;

  * Uniformity across languages - the norm is stated collection-agnostic.

* Examples:

  * Case #1:

    * Incorrect:

      ```javascript
      const options = {
          zIndex: 10,
          alignItems: "center",
          margin: 0,
      };
      ```

    * Correct (a blank line is a partition):

      ```javascript
      const options = {
          alignItems: "center",
          zIndex: 10,

          margin: 0,
      };
      ```
