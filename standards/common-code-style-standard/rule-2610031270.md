# The Rosinfotech Base Standards

## The Common Code Style Standard

### Formatting

#### Rule #2610031270

* Context:

  * Half-broken constructs - some items on one line, some on the next - combine the drawbacks of both layouts;

* Description:

  * Braces are required for multiline conditions and loops (`curly: multi-line`);

  * An object-like literal is either fully on one line or one item per line - consistently (`object-curly-newline` consistent, `object-property-newline`, `function-call-argument-newline: consistent`); the same for import/export declarations;

  * When an expression breaks, the operator starts the continuation line; `?` and `:` also go before the break (`operator-linebreak: before`);

  * Enforcement - the rule is supported by the repository [eslint-config-javascript](https://github.com/rosinfotech/eslint-config-javascript);

* Benefits:

  * One predictable layout per construct;

  * Continuation lines are identifiable by their leading operator;

  * Review diffs stay minimal on reflow.

* Examples:

  * Case #1:

    * Incorrect:

      ```javascript
      const options = { align: "center", zIndex: 10,
          margin: 0 };
      const total = price +
          tax;
      ```

    * Correct:

      ```javascript
      const options = {
          align: "center",
          zIndex: 10,
          margin: 0,
      };
      const total =
          price + tax;
      ```
