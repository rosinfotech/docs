# The Rosinfotech Base Standards

## The Common Code Style Standard

### Formatting

#### Rule #2610031268

* Context:

  * Whitespace is symmetric or absent - half-spaced operators and braces read as typos;

* Description:

  * Spaces around infix operators (`space-infix-ops`) and after commas and colons (`key-spacing`, `switch-colon-spacing`);

  * A space before every opening block brace (`space-before-blocks: always`); unary operators stay unspaced (`space-unary-ops`);

  * A space after the comment marker (`spaced-comment: always`);

  * In multiline object-like literals the colons are aligned (`key-spacing` multiLine align: colon);

  * A space inside braces of object literals and templates (`object-curly-spacing: always`, prettier `bracketSpacing: true`; `template-curly-spacing: never` inside interpolations);

  * Enforcement - the rule is supported by the repositories [eslint-config-javascript](https://github.com/rosinfotech/eslint-config-javascript) and [prettier-config-standard](https://github.com/rosinfotech/prettier-config-standard);

* Benefits:

  * Uniform reading rhythm;

  * Aligned colons make multiline maps scannable;

  * The formatter output matches the linter.

* Examples:

  * Case #1:

    * Incorrect:

      ```javascript
      if (a===b) {return a+b;}
      ```

    * Correct:

      ```javascript
      if (a === b) {
          return a + b;
      }
      ```
