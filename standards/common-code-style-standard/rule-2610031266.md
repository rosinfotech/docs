# The Rosinfotech Base Standards

## The Common Code Style Standard

### Formatting

#### Rule #2610031266

* Context:

  * Empty lines are the paragraph breaks of code; without discipline they are either noise or missing separation;

* Description:

  * At most 2 consecutive empty lines inside a file, at most 1 at the file end, none at the file start (`no-multiple-empty-lines`: max 2, maxEOF 1, maxBOF 0);

  * The file ends with a single newline;

  * Functions and classes are separated from the surrounding code by a blank line (`padding-line-between-statements`: always around function/class);

  * Two blank lines separate the import block from the code (see [Rule #2610031258](/standards/common-code-style-standard/rule-2610031258.md));

  * Enforcement - the rule is supported by the repositories [eslint-config-javascript](https://github.com/rosinfotech/eslint-config-javascript) and [eslint-config-import](https://github.com/rosinfotech/eslint-config-import);

* Benefits:

  * Predictable visual density;

  * Logical blocks stay visually separated;

  * No editor-specific newline artifacts.

* Examples:

  * Case #1:

    * Incorrect:

      ```javascript
      function first() {





      }
      function second() { }
      ```

    * Correct:

      ```javascript
      function first() { }

      function second() { }
      ```
