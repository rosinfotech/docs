# The Rosinfotech Base Standards

## The Common Code Style Standard

### Expressions

#### Rule #2610031262

* Context:

  * Implicit conversions and verbose canonical forms hide intent; empty blocks hide bugs;

* Description:

  * No empty blocks; an empty `catch` is the only allowed empty block and must be explicit (`no-empty` with `allowEmptyCatch`);

  * No implicit type coercion; the explicit `!!` and `~` conversions are allowed (`no-implicit-coercion`);

  * The canonical shorthand form is preferred (`eslint-config-javascript`):

    * object shorthand methods and properties (`object-shorthand: always`);

    * arrow callbacks instead of anonymous function expressions (`prefer-arrow-callback`);

    * template literals instead of string concatenation (`prefer-template`);

    * numeric literals instead of `parseInt` (`prefer-numeric-literals`);

    * object spread instead of `Object.assign` (`prefer-object-spread`);

    * compound assignment operators (`operator-assignment: always`);

  * Enforcement - the rule is supported by the repository [eslint-config-javascript](https://github.com/rosinfotech/eslint-config-javascript);

* Benefits:

  * Intent stays visible - conversions and constructs are explicit;

  * The codebase uses one canonical form per construct;

  * Empty blocks never mask unfinished logic (except the intentional empty catch).

* Examples:

  * Case #1:

    * Incorrect:

      ```javascript
      const n = parseInt("10", 2);
      const copy = Object.assign({}, source);
      if (value === true) { }
      ```

    * Correct:

      ```javascript
      const n = 0b1010;
      const copy = { ...source };
      try { risky(); } catch (_error) { }
      ```
