# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2610031908

* Context:

  * Agents routinely write small helper scripts for their micro-tasks - the practice is known as ad-hoc (one-off, ephemeral) scripting - and without a fixed home these scripts scatter over the project;

* Description:

  * When the agent needs a helper script for its own work - a technical micro-task such as:

    * targeted file parsing;

    * converting a file from one format to another;

    * an internet search and/or data scraping within the assigned task;

  * The script lives in the `.agents/` directory of the project root - a dedicated home for the agent tooling, separate from the project's own scripts - and runs on Node.js (JavaScript), regardless of the project's own stack;

  * Dependency discipline:

    * prefer Node built-ins (`fs`, the global `fetch`, `crypto`, `zlib` and others) - the scripts stay zero-dependency whenever possible;

    * when a dependency is unavoidable, `npm init -y` and `npm install` run INSIDE `.agents/` - creating its own `package.json` and `node_modules` there - never in the project root: the agent tooling must not touch the dependency set of the project;

  * The rule covers the agent's working tooling only - the project source code follows the project's language and structure;

  * The script files follow the code style standards of this catalog;

* Benefits:

  * One predictable home for the agent tooling - no scatter;

  * A uniform runtime - the scripts run everywhere Node.js runs, in any project;

  * Zero-dependency by default - Node built-ins cover parsing, fetching and conversion;

  * The project source and dependencies stay untouched - the tooling installs inside `.agents/`.

* Examples:

  * Case #1:

    * the user asks to convert `data.csv` into TSV and count the rows;

    * the agent writes `.agents/convertCsvToTsv.js` and runs it with `node .agents/convertCsvToTsv.js`;

  * Case #2 - a non-JavaScript project:

    * in a Go repository the agent needs to scrape a documentation page;

    * the helper still goes to `.agents/` on Node.js - never into the Go sources.
