# The Rosinfotech Base Standards

## The AI Standard

### The AI Automation Standard

#### Rule #2609271120

* Context:

  * Project AGENTS.md files differ from project to project; without a fixed composition they drift and agents miss key project knowledge.

* Description:

  * The Project AGENTS.md follows the composition (the skeleton is the asset [AGENTS-STANDARD-2.md](/standards/ai-standard/assets/AGENTS-STANDARD-2.md)):

    * Project overview: 1-3 sentences - what the project is, the stack, what makes it different;

    * Commands: install dependencies, lint, format, type-check, tests (single file / all), build, dev server / run;

    * Architecture notes: key entry points, layout decisions, what not to touch, non-obvious dependencies;

    * Conventions: the project-relevant catalog rules linked by reference (rule inclusion per [Rule #2609262010](/standards/ai-standard/rule-2609262010.md)) - never restated;

    * Tools and integrations: tool-specific rules kept abstract - no IPs, no tokens, no client IDs (see [Rule #2609270958](/standards/security-standard/rule-2609270958.md));

    * Safety notes: project-specific secrets, environments, deployment constraints.

* Benefits:

  * Any agent onboards onto a project from a single file;

  * Uniform structure across projects;

  * No duplication of catalog rules.

* Examples:

  * Case #1:

    * Incorrect:

      * a Project AGENTS.md containing only a command list;

    * Correct:

      * all applicable sections filled in, the inapplicable ones removed.
