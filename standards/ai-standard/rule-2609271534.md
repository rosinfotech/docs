# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2609271534

* Context:

  * Java backend services need a role profile that fixes the language toolchain and keeps the agent inside the backend boundary.

* Description:

  * The Java Backend Engineer AGENTS.md is a role file: it extends the BASE AGENTS.md ([Rule #2609271528](/standards/ai-standard/rule-2609271528.md)) and never weakens it; the ready-to-copy source of truth is the asset [AGENTS-STANDARD-BACKEND-JAVA.md](/standards/ai-standard/assets/AGENTS-STANDARD-BACKEND-JAVA.md);

  * Role scope: backend services, background workers and CLIs in Java - API implementation, business logic, data access, integration clients, tests; frontend and infrastructure work stay outside the role;

  * The build tool (Maven or Gradle) is the single source of commands: build, lint (the configured static analysis, e.g. Checkstyle or Spotless), tests, packaging - the agent takes the exact commands from the project build config and Makefile, never invents them;

  * The JDK version is a project decision read from the repository build config - the role file stays version-neutral;

  * The code follows the language-idiomatic conventions plus the Common Code Style Standard rules applicable to Java:

    * [Rule #2103051010](/standards/common-code-style-standard/rule-2103051010.md) - UTLBL;

    * [Rule #2103052001](/standards/common-code-style-standard/rule-2103052001.md) - from general to specific;

    * [Rule #2108211519](/standards/common-code-style-standard/rule-2108211519.md) - abbreviations in uppercase;

    * [Rule #2601190149](/standards/common-code-style-standard/rule-2601190149.md) - directories: kebab case;

    * [Rule #2601190212](/standards/common-code-style-standard/rule-2601190212.md) - backend files: camel case + suffix;

    * [Rule #2601190214](/standards/common-code-style-standard/rule-2601190214.md) - bash files: snake case;

    * The path and file variable suffixes:

      * [Rule #2108211636](/standards/common-code-style-standard/rule-2108211636.md) - `...File` (file name with extension);

      * [Rule #2108211643](/standards/common-code-style-standard/rule-2108211643.md) - `...FileNoExtension` (file name without extension);

      * [Rule #2108211646](/standards/common-code-style-standard/rule-2108211646.md) - `...Path` (directory path);

      * [Rule #2108211652](/standards/common-code-style-standard/rule-2108211652.md) - `...Directory` (directory name);

      * [Rule #2108211659](/standards/common-code-style-standard/rule-2108211659.md) - `...PathFile` (path to a concrete file);

    * [Rule #2109011651](/standards/common-code-style-standard/rule-2109011651.md) - function arguments: up to 3 required + options object;

    * [Rule #2609270950](/standards/common-code-style-standard/rule-2609270950.md) - indentation: 4 spaces;

    * [Rule #2609270952](/standards/common-code-style-standard/rule-2609270952.md) - TSV over CSV;

  * The TypeScript type rules [Rule #2605280101](/standards/common-code-style-standard/rule-2605280101.md) and [Rule #2605280102](/standards/common-code-style-standard/rule-2605280102.md) are excluded - TypeScript only;

  * Stack specifics (framework, build tool, DB access layer, migration tool) are project decisions - the agent reads them from the repository itself (the build config, Makefile), never invents or replaces them;

  * Placement: the user-global agent config and/or the repository root.

* Benefits:

  * The agent always runs the project-configured build pipeline instead of guessing commands;

  * The role boundary prevents a backend agent from drifting into frontend or infrastructure work;

  * Project stack changes never require role file edits.

* Examples:

  * Case #1:

    * Incorrect:

      * the agent runs `mvn verify` in a Gradle repository because the role file pinned Maven;

    * Correct:

      * the role file delegates the build tool choice to the repository and reads the commands from the project build config.
