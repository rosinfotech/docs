# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2610031427

* Context:

  * The composition of an AGENTS.md must be operable in place and sourced from the single source of truth - the standards repository - not from scattered neighbor files;

* Description:

  * The inclusion sources are the role assets of the standards repository `rosinfotech/standards` (branch `master`), the directory `standards/ai-standard/assets/` - the files matching `AGENTS-*.md`;

  * The link base of the assets:

    * the listing: `https://api.github.com/repos/rosinfotech/standards/contents/standards/ai-standard/assets`;

    * the raw form: `https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/<file>`;

  * TRIGGER: the user asks to include roles ("подключи роль", "включи агентов", "include agents") or to refresh ("обнови включения", "update inclusions");

  * On the trigger the agent:

    * refreshes the link base first: fetches the listing and filters the `AGENTS-*.md` files;

    * replaces every existing marked block with the current content fetched from its URL (the update path runs before the new inclusions);

    * selects the asset semantically closest to the user's request - by the file name and the role it encodes; several close candidates or an unclear choice - asks first (button choice, [Rule #2609271000](/standards/ai-standard/rule-2609271000.md));

    * fetches the selected asset and appends it as a marked block at the end of the file, after the base content;

    * never modifies anything outside the marked blocks;

    * a block whose source URL is unreachable - reports it and leaves the block untouched;

  * The marked block carries the full source URL in both markers:

    ```text
    <!-- AGENTS-INCLUDE: https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/AGENTS-STANDARD-FRONTEND-REACT.md -->
    ...the full content of the asset...
    <!-- /AGENTS-INCLUDE: https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/AGENTS-STANDARD-FRONTEND-REACT.md -->
    ```

  * The included asset keeps its own heading - the block is self-contained and needs no wrapping;

  * The precedence stays: the base rules win over any included content (the model [Rule #2609262010](/standards/ai-standard/rule-2609262010.md));

* Benefits:

  * Single source of truth - the composition always pulls the current assets from the repository;

  * Semantic pick - the engineer names the role, the agent maps it to the asset;

  * Idempotent refresh - one command re-fetches every inclusion;

  * The base stays intact - the marked blocks are the only mutable zone.

* Examples:

  * Case #1 - include:

    * the user: "подключи роль фронтендендера";

    * the agent refreshes the listing, picks `AGENTS-STANDARD-FRONTEND-REACT.md` as the closest by meaning, fetches it and appends the marked block with its full content;

  * Case #2 - update:

    * the user: "обнови включения";

    * the agent re-fetches every existing marked block's URL and replaces the block content with the current version - the rest of AGENTS.md is untouched.
