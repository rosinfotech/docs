# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2609271536

* Context:

  * TypeScript backend services on Node.js need a role profile that fixes the language toolchain and keeps the agent inside the backend boundary.

* Description:

  * The TypeScript (NodeJS) Backend Engineer AGENTS.md is a role asset: composed into an AGENTS.md as a marked block on demand (the inclusions: [Rule #2610031427](/standards/ai-standard/rule-2610031427.md)); the ready-to-copy source of truth is the asset [AGENTS-STANDARD-BACKEND-TYPESCRIPT.md](/standards/ai-standard/assets/AGENTS-STANDARD-BACKEND-TYPESCRIPT.md);

  * Role scope:

    * backend services, background workers and CLIs in TypeScript on Node.js;

    * API implementation, business logic, data access, integration clients, tests;

  * Frontend and infrastructure work stay outside the role;

  * The npm scripts in package.json are the single source of commands:

    * install;

    * lint;

    * format;

    * type-check (`tsc --noEmit`);

    * tests (the configured runner);

    * build;

    * run;

  * The agent takes the exact commands from the project package.json and Makefile, never invents them;

  * The Node.js and npm version requirements are project decisions - the agent reads them from the repository (package.json engines, the Makefile); the role file stays version-neutral;

  * The code follows the Common Code Style Standard rules applicable to TypeScript on Node.js:

    * [Rule #2103051010](/standards/common-code-style-standard/rule-2103051010.md) - UTLBL;

    * [Rule #2103052001](/standards/common-code-style-standard/rule-2103052001.md) - from general to specific;

    * [Rule #2108211519](/standards/common-code-style-standard/rule-2108211519.md) - abbreviations in uppercase;

    * [Rule #2601190149](/standards/common-code-style-standard/rule-2601190149.md) - directories: kebab case;

    * [Rule #2601190212](/standards/common-code-style-standard/rule-2601190212.md) - backend files: camel case + suffix;

    * [Rule #2601190214](/standards/common-code-style-standard/rule-2601190214.md) - bash files: snake case;

    * The path and file variable suffixes:

      * [Rule #2108211636](/standards/common-code-style-standard/rule-2108211636.md) - `...File` (file name with extension);

      * [Rule #2108211643](/standards/common-code-style-standard/rule-2108211643.md) - `...FileNoExtension` (file name without extension);

      * [Rule #2108211646](/standards/common-code-style-standard/rule-2108211646.md) - `...Path` (directory path);

      * [Rule #2108211652](/standards/common-code-style-standard/rule-2108211652.md) - `...Directory` (directory name);

      * [Rule #2108211659](/standards/common-code-style-standard/rule-2108211659.md) - `...PathFile` (path to a concrete file);

    * [Rule #2109011651](/standards/common-code-style-standard/rule-2109011651.md) - function arguments: up to 3 required + options object;

    * [Rule #2610031256](/standards/common-code-style-standard/rule-2610031256.md) - collections: alphabetical sorting;

    * [Rule #2610031258](/standards/common-code-style-standard/rule-2610031258.md) - imports - order, hygiene, no cycles;

    * [Rule #2610031260](/standards/common-code-style-standard/rule-2610031260.md) - declare before use, one per statement, prefer const;

    * [Rule #2610031262](/standards/common-code-style-standard/rule-2610031262.md) - explicit expressions and canonical shorthands;

    * [Rule #2610031264](/standards/common-code-style-standard/rule-2610031264.md) - line formatting - length 100, LF, no BOM;

    * [Rule #2610031266](/standards/common-code-style-standard/rule-2610031266.md) - empty lines discipline;

    * [Rule #2610031268](/standards/common-code-style-standard/rule-2610031268.md) - operator and brace spacing;

    * [Rule #2610031270](/standards/common-code-style-standard/rule-2610031270.md) - multiline consistency;

    * [Rule #2609270950](/standards/common-code-style-standard/rule-2609270950.md) - indentation: 4 spaces;

    * [Rule #2610031272](/standards/common-code-style-standard/rule-2610031272.md) - markdown lists: indentation step 2;

    * [Rule #2609270952](/standards/common-code-style-standard/rule-2609270952.md) - TSV over CSV;

  * The code follows the JavaScript Code Style Standard:

    * [Rule #2605280102](/standards/javascript-code-style-standard/rule-2605280102.md) - unused variables: underscore prefix;

    * [Rule #2610031274](/standards/javascript-code-style-standard/rule-2610031274.md) - string and statement formatting;

    * [Rule #2610031276](/standards/javascript-code-style-standard/rule-2610031276.md) - formatter precedence: prettier owns the layout;

  * The code follows the TypeScript Code Style Standard:

    * [Rule #2605280101](/standards/typescript-code-style-standard/rule-2605280101.md) - type naming prefixes I, T, E, G;

    * [Rule #2610031278](/standards/typescript-code-style-standard/rule-2610031278.md) - type-only imports: separate statement;

  * Stack specifics (framework, test runner, DB access layer, migration tool) are project decisions - the agent reads them from the repository itself (package.json, Makefile, build config), never invents or replaces them;

  * Placement: the user-global agent config and/or the repository root.

* Benefits:

  * The agent always runs the project-configured scripts instead of guessing commands;

  * The role boundary prevents a backend agent from drifting into frontend or infrastructure work;

  * Project stack changes never require role file edits.

* Examples:

  * Case #1:

    * Incorrect:

      * the agent runs `jest` in a repository whose package.json defines `vitest`;

    * Correct:

      * the agent reads the test script from package.json and runs what the project defines.
