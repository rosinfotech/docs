# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2609262010

* Context:

  * AI coding agents (Claude Code, Codex and others) load instruction files named `AGENTS.md` from several locations: the user-global agent config, the repository root and subdirectories; without a fixed model the files drift and agents miss critical prohibitions.

* Description:

  * The company AGENTS.md model consists of the BASE AGENTS.md and the role AGENTS.md files:

    * The BASE AGENTS.md - universal agent behavior, identical everywhere; the composition is fixed by [Rule #2609271528](/standards/ai-standard/rule-2609271528.md); the source of truth is the asset [AGENTS-STANDARD-BASE.md](/standards/ai-standard/assets/AGENTS-STANDARD-BASE.md);

    * The role AGENTS.md files - the role scope and the role toolchain (architect, backend engineer, frontend engineer); each role file is fixed by its rule in this subsection and has its ready-to-copy asset;

  * A role file extends the BASE AGENTS.md and NEVER weakens it: when a role rule conflicts with the base, the base wins;

  * Role files are independent of each other: an engineer may install several (e.g. a backend role together with a frontend role) - the roles do not share state and never contradict each other;

  * Rule inclusion: abstract norms live in the standards catalog (The Rosinfotech Base Standards); an AGENTS.md file is a composition - it inlines the agent-relevant text of the rules it includes with their full meaning, not references (an agent can not follow external links and must not be tempted to fetch or analyze them); rule IDs and links appear only where the file needs them on purpose - e.g. the lint config repositories an agent applies in repositories; the catalog is the single source of truth - when a catalog rule changes, the AGENTS.md assets are updated from it;

  * Placement: the user-global agent config on the engineer's machine and/or the repository root;

  * Project-specific knowledge (commands, stack, architecture) is not carried by AGENTS.md files - the agent reads it from the repository itself: the Makefile, package.json and the build config.

* Benefits:

  * Uniformity - predictable agent behavior everywhere;

  * No duplication - shared rules are written once and updated in one place;

  * Safety - critical prohibitions (git, secrets) can not be weakened by a role file.

* Examples:

  * Case #1 - conflict resolution:

    * Incorrect:

      * a role AGENTS.md says "commit after successful tests" and the agent commits;

    * Correct:

      * the base says git writes require an explicit order - the base wins, no commit happens without it;

  * Case #2 - project knowledge:

    * the agent needs the test command - it reads the Makefile / package.json of the repository, not an AGENTS.md file.
