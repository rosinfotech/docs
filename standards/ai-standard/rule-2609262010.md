# The Rosinfotech Base Standards

## The AI Standard

### The AI Automation Standard

#### Rule #2609262010

* Context:

  * AI coding agents (Claude Code, Codex and others) load instruction files named `AGENTS.md` from several locations: the user-global agent config, the repository root and subdirectories;

* Description:

  * The company AGENTS.md standard consists of two levels:

    * Level 1 - Base AGENTS.md - universal agent behavior plus the company makefile workflow; identical for every company project; source of truth is the asset [AGENTS-STANDARD-1.md](/standards/ai-standard/assets/AGENTS-STANDARD-1.md);

    * Level 2 - Project AGENTS.md - project commands, architecture notes, project conventions and tool-specific rules of the concrete project; the skeleton is the asset [AGENTS-STANDARD-2.md](/standards/ai-standard/assets/AGENTS-STANDARD-2.md);

  * Level 2 extends Level 1 and NEVER weakens it: when a project rule conflicts with a base rule, the base rule wins;

  * Placement: Level 1 is installed into the user-global agent config on the engineer's machine and/or committed at the repository root; Level 2 is committed at the repository root of the project and may be repeated in subdirectories for a narrower scope;

  * Rule inclusion: abstract norms live in the standards catalog (The Rosinfotech Base Standards); an AGENTS.md file is a composition - it inlines the agent-relevant text of the rules it includes (an agent can not follow external links) and marks each rule with its rule ID; the catalog is the single source of truth - when a catalog rule changes, the AGENTS.md templates are updated from it;

  * Level composition - the rules the AGENTS.md files cover:

    * Level 1 - Base AGENTS.md (the asset [AGENTS-STANDARD-1.md](/standards/ai-standard/assets/AGENTS-STANDARD-1.md)) covers:

      * [Rule #2609262015](/standards/ai-standard/rule-2609262015.md) - git: no write operations without an explicit order;

      * [Rule #2609270958](/standards/security-standard/rule-2609270958.md) with [Rule #2609262020](/standards/ai-standard/rule-2609262020.md) - sensitive information and the agent-side diff scan;

      * [Rule #2609270956](/standards/documentation-standard/rule-2609270956.md) with [Rule #2609262025](/standards/ai-standard/rule-2609262025.md) - git references and the agent-side link formatting;

      * [Rule #2609271000](/standards/ai-standard/rule-2609271000.md) - interactive work: step by step;

      * [Rule #2609262030](/standards/ai-standard/rule-2609262030.md) - commit requests: preparation flow only;

      * [Rule #2609262035](/standards/ai-standard/rule-2609262035.md) - repository initialization: ask before init;

    * Level 2 - Project AGENTS.md (the asset [AGENTS-STANDARD-2.md](/standards/ai-standard/assets/AGENTS-STANDARD-2.md)) covers:

      * this rule - the hierarchy and the rule inclusion mechanism;

      * [Rule #2609271120](/standards/ai-standard/rule-2609271120.md) - the Project AGENTS.md composition;

      * the project-relevant catalog rules, linked by reference.

* Benefits:

  * Uniformity - predictable agent behavior across all company projects;

  * No duplication - shared rules are written once and updated in one place;

  * Safety - critical prohibitions (git, secrets) can not be accidentally weakened by a project file;

* Examples:

  * Case #1 - placement:

    ```text
    <project-root>/
      AGENTS.md          # Level 2 (project rules); Level 1 may be committed here as well
      docs/
      src/
    ```

  * Case #2 - conflict resolution:

    * Incorrect:

      * A project `AGENTS.md` says "commit after successful tests" and the agent commits;

    * Correct:

      * The base says git writes require an explicit order - the base wins, no commit happens without it;
