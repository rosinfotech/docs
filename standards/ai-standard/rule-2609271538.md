# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2609271538

* Context:

  * React frontend applications need a role profile that fixes the company stack and keeps the agent inside the frontend boundary.

* Description:

  * The Frontend Engineer AGENTS.md is a role file: it extends the BASE AGENTS.md ([Rule #2609271528](/standards/ai-standard/rule-2609271528.md)) and never weakens it; the ready-to-copy source of truth is the asset [AGENTS-STANDARD-FRONTEND-REACT.md](/standards/ai-standard/assets/AGENTS-STANDARD-FRONTEND-REACT.md);

  * Role scope: web applications and mobile application shells in TypeScript + React - UI implementation, routing, state, API client, component tests; backend and infrastructure work stay outside the role;

  * The company frontend stack (the source of truth: the Rosinfotech frontend boilerplates `boilerplate-frontend-tanstack-router` and `boilerplate-frontend-nextjs`):

    * Core: TypeScript 6, React 19, Node.js 22+ with npm 9+;

    * UI: Ant Design 6 components, Tailwind CSS 4 styling, `clsx` for class composition;

    * State and data: Zustand 5 stores, Zod 4 validation schemas;

    * Two framework tracks: Vite 7 with TanStack Router/Start (the SPA/SSR track) and Next.js 16 (the SSR track) - the track is read from the repository (package.json, the lockfile);

    * Mobile: Capacitor 8 wraps the web build into iOS/Android applications;

    * Quality toolchain: ESLint, Prettier, Stylelint with the shared `@rosinfo.tech/*` configs, Vitest tests, husky with lint-staged (the pre-push chain: format, stylelint, lint), `tsc --noEmit` type-check;

    * Environment: per-environment `.env` files in the `envs/` directory loaded via dotenv-cli;

  * The npm scripts in package.json are the single source of commands: the agent takes the exact commands from the project package.json and Makefile, never invents them;

  * The code follows the Common Code Style Standard rules applicable to the TypeScript + React frontend:

    * [Rule #2103051010](/standards/common-code-style-standard/rule-2103051010.md) - UTLBL;

    * [Rule #2103052001](/standards/common-code-style-standard/rule-2103052001.md) - from general to specific;

    * [Rule #2108211519](/standards/common-code-style-standard/rule-2108211519.md) - abbreviations in uppercase;

    * [Rule #2601190149](/standards/common-code-style-standard/rule-2601190149.md) - directories: kebab case;

    * [Rule #2601190331](/standards/common-code-style-standard/rule-2601190331.md) - frontend files: kebab case;

    * [Rule #2601190333](/standards/common-code-style-standard/rule-2601190333.md) - React components: camel case;

    * [Rule #2601190214](/standards/common-code-style-standard/rule-2601190214.md) - bash files: snake case;

    * The path and file variable suffixes:

      * [Rule #2108211636](/standards/common-code-style-standard/rule-2108211636.md) - `...File` (file name with extension);

      * [Rule #2108211643](/standards/common-code-style-standard/rule-2108211643.md) - `...FileNoExtension` (file name without extension);

      * [Rule #2108211646](/standards/common-code-style-standard/rule-2108211646.md) - `...Path` (directory path);

      * [Rule #2108211652](/standards/common-code-style-standard/rule-2108211652.md) - `...Directory` (directory name);

      * [Rule #2108211659](/standards/common-code-style-standard/rule-2108211659.md) - `...PathFile` (path to a concrete file);

    * [Rule #2109011651](/standards/common-code-style-standard/rule-2109011651.md) - function arguments: up to 3 required + options object;

    * [Rule #2610031256](/standards/common-code-style-standard/rule-2610031256.md) - collections: alphabetical sorting;

    * [Rule #2610031258](/standards/common-code-style-standard/rule-2610031258.md) - imports: order, hygiene, no cycles;

    * [Rule #2610031260](/standards/common-code-style-standard/rule-2610031260.md) - declare before use, one per statement, prefer const;

    * [Rule #2610031262](/standards/common-code-style-standard/rule-2610031262.md) - explicit expressions and canonical shorthands;

    * [Rule #2610031264](/standards/common-code-style-standard/rule-2610031264.md) - line formatting: length 100, LF, no BOM;

    * [Rule #2610031266](/standards/common-code-style-standard/rule-2610031266.md) - empty lines discipline;

    * [Rule #2610031268](/standards/common-code-style-standard/rule-2610031268.md) - operator and brace spacing;

    * [Rule #2610031270](/standards/common-code-style-standard/rule-2610031270.md) - multiline consistency;

    * [Rule #2609270950](/standards/common-code-style-standard/rule-2609270950.md) - indentation: 4 spaces;

    * [Rule #2610031272](/standards/common-code-style-standard/rule-2610031272.md) - markdown lists: indentation step 2;

    * [Rule #2609270952](/standards/common-code-style-standard/rule-2609270952.md) - TSV over CSV;

  * The code follows the JavaScript Code Style Standard:

    * [Rule #2605280102](/standards/javascript-code-style-standard/rule-2605280102.md) - unused variables: underscore prefix;

    * [Rule #2610031274](/standards/javascript-code-style-standard/rule-2610031274.md) - string and statement formatting;

    * [Rule #2610031276](/standards/javascript-code-style-standard/rule-2610031276.md) - formatter precedence: prettier owns the layout;

  * The code follows the TypeScript Code Style Standard:

    * [Rule #2605280101](/standards/typescript-code-style-standard/rule-2605280101.md) - type naming prefixes I, T, E, G;

    * [Rule #2610031278](/standards/typescript-code-style-standard/rule-2610031278.md) - type-only imports: separate statement;

  * The code follows the React Code Style Standard:

    * [Rule #2610031280](/standards/react-code-style-standard/rule-2610031280.md) - hooks discipline;

    * [Rule #2610031282](/standards/react-code-style-standard/rule-2610031282.md) - JSX formatting;

    * [Rule #2610031284](/standards/react-code-style-standard/rule-2610031284.md) - fast refresh exports;

  * The code follows the CSS Code Style Standard:

    * [Rule #2610031286](/standards/css-code-style-standard/rule-2610031286.md) - style formatting;

    * [Rule #2610031288](/standards/css-code-style-standard/rule-2610031288.md) - property order;

  * The backend file naming rule [Rule #2601190212](/standards/common-code-style-standard/rule-2601190212.md) is excluded - backend only;

  * The framework track (TanStack or Next.js) is fixed by the project itself - the agent reads it from the repository (package.json, the lockfile) and never chooses ad hoc; on a conflict with the BASE AGENTS.md, the base wins;

  * Placement: the user-global agent config and/or the repository root.

* Benefits:

  * The agent knows the company stack without rediscovering it per project;

  * Component libraries, styling and state approaches stay uniform across frontend projects;

  * Switching a project between the two framework tracks changes only the repository config, not the role file.

* Examples:

  * Case #1:

    * Incorrect:

      * the agent adds a Redux dependency to a Zustand project because "Redux is the standard";

    * Correct:

      * the role file names Zustand the company state tool; the agent builds on the project's existing stores.
