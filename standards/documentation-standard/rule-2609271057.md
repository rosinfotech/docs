# The Rosinfotech Base Standards

## The Documentation Standard

### Rules

#### Rule #2609271057

* Context:

  * Rules must be uniquely identifiable and uniformly described across all standards.

* Description:

  * A rule file is named `rule-<UTLBL>.md`, where `<UTLBL>` is the rule identifier in the short form of [Rule #2103051010](/standards/common-code-style-standard/rule-2103051010.md) (YYMMDDHHMM);

  * The rule is referenced by its identifier: `Rule #<UTLBL>`;

  * The rule description follows the scheme - the ready-to-copy template asset [scheme.md](/standards/documentation-standard/assets/scheme.md):

    * Context - why the rule exists;

    * Description - the norm;

    * Benefits - what the norm gives;

    * Examples - with Incorrect/Correct cases where applicable;

  * Every section of the scheme is filled in;

  * The rule files use basic Markdown syntax (the reference: https://www.markdownguide.org/basic-syntax/);

  * The heading chain inside a rule file: `# The Rosinfotech Base Standards` → `## <The X Standard>` → `### <subsection>` → `#### Rule #<UTLBL>` - one level deeper where the standard's subsections have their own groups (the Name Convention rules);

  * Lists inside rule descriptions follow [Rule #2609270954](/standards/documentation-standard/rule-2609270954.md) (Progressive Disclosure).

* Benefits:

  * Unique and sortable rule identifiers (UTLBL);

  * Uniform rule anatomy: any rule is readable by anyone without a legend;

  * A new rule is created by copying the scheme.

* Examples:

  * Case #1 - naming:

    * Incorrect:

      * `240115_naming.md`, `rule-new.md`, `Rule 12`;

    * Correct:

      * the file `rule-2609271057.md` referenced as `Rule #2609271057`;

  * Case #2 - heading chain:

    ```markdown
    # The Rosinfotech Base Standards

    ## The Security Standard

    ### Sensitive data

    #### Rule #2609270958
    ```
