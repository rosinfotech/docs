# The Rosinfotech Base Standards

## The Documentation Standard

### References

#### Rule #2609270956

* Context:

  * Links to a branch head rot: the file changes or moves, and the link starts showing different content; links without line anchors make the reader search for the fragment;

* Description:

  * When making a link to a file (or a file fragment) in a git repository, ALWAYS pin it to a concrete commit (SHA) - not to a branch head;

  * When referencing specific lines, ALWAYS add line anchors to the link;

  * URL formats:

    * GitLab: `https://<host>/<group>/<repo>/-/blob/<sha>/<relative/path>#L<start>-<end>`;

    * GitHub: `https://<host>/<org>/<repo>/blob/<sha>/<relative/path>#L<start>-L<end>`;

  * Use the commit SHA being discussed (stable link); the default branch name is acceptable only when the SHA is unknown;

* Benefits:

  * Stability - the link shows the same content forever;

  * Exact context - the reader lands on the exact lines;

  * Reviewable record - the referenced commit becomes part of the discussion record;

* Examples:

  * Case #1:

    * Incorrect (branch head, no line anchors):

      ```text
      https://gitlab.com/group/repo/-/blob/main/src/app.ts
      ```

    * Correct (commit SHA + line anchor):

      ```text
      https://gitlab.com/group/repo/-/blob/1f2a3b4/src/app.ts#L26-44
      ```
