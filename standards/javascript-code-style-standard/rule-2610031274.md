# The Rosinfotech Base Standards

## The JavaScript Code Style Standard

### Strings and Statements

#### Rule #2610031274

* Context:

  * JavaScript string and statement punctuation needs one fixed style - the languages's most contentious characters (quotes, semicolons, commas) must not vary per author;

* Description:

  * Double quotes for strings (`singleQuote: false`); object properties are quoted only as needed (`quoteProps: "as-needed"`); single quotes stay for strings containing double quotes;

  * Semicolons are required; the semicolon stays on the last line of the statement (`semi: true`, `semi-style: last`);

  * Trailing commas where valid in ES5 (`trailingComma: "es5"`);

  * A single-parameter arrow function omits the parentheses (`arrowParens: "avoid"`); zero and multiple parameters keep them;

  * No space inside template literal interpolations (`template-curly-spacing: never`); no space before template tags (`template-tag-spacing: never`);

  * An IIFE is wrapped in parentheses and invoked from outside (`wrap-iife: outside`); a broken regex literal is wrapped (`wrap-regex`);

  * Enforcement - the rule is supported by the repository [prettier-config-standard](https://github.com/rosinfotech/prettier-config-standard);

* Benefits:

  * One canonical string and statement form;

  * Deterministic formatter output;

  * Minimal diff noise on parameter changes.

* Examples:

  * Case #1:

    * Incorrect:

      ```javascript
      import x from 'module';
      const fn = (value) => 'result: ' + value;
      ```

    * Correct:

      ```javascript
      import x from "module";
      const fn = value => `result: ${value}`;
      ```
