# The Rosinfotech Base Standards

## The JavaScript Code Style Standard

### Tooling

#### Rule #2610031276

* Context:

  * A formatter (Prettier) and a linter (ESLint) both reformat code; without a fixed precedence they fight each other and flip-flop the output;

* Description:

  * Prettier owns the final formatting output: the ESLint rules that conflict with it are disabled (`quotes`, `semi`, `keyword-spacing`, `function-paren-newline`, `quote-props` and others are off in [eslint-config-javascript](https://github.com/rosinfotech/eslint-config-javascript));

  * `eslint-config-prettier` is applied last in the ESLint config chain - it turns the remaining conflicting rules off;

  * ESLint keeps everything Prettier does not decide:

    * sorting;

    * imports;

    * declarations;

    * expressions (the rules of this standard);

  * The project pipeline runs the linter and the formatter in one pass - never reformat in two competing tools;

  * Enforcement - the rule is supported by the repositories [eslint-config-javascript](https://github.com/rosinfotech/eslint-config-javascript) and [prettier-config-standard](https://github.com/rosinfotech/prettier-config-standard);

* Benefits:

  * No formatter/linter wars - the output is deterministic;

  * Each tool does its own job:

    * Prettier - layout;

    * ESLint - semantics and structure;

  * IDE auto-fix matches CI.

* Examples:

  * Case #1:

    * Incorrect:

      * an ESLint rule enforces single quotes while Prettier rewrites them to double - `lint` and `format` flip-flop;

    * Correct:

      * quotes are decided by Prettier alone; ESLint's `quotes` is off.
