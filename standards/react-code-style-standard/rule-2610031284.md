# The Rosinfotech Base Standards

## The React Code Style Standard

### Exports

#### Rule #2610031284

* Context:

  * Mixed exports from a component file break Fast Refresh: editing such a file reloads the whole module and loses component state;

* Description:

  * A component file exports only components; exporting constants alongside is allowed (`react-refresh/only-export-components` with `allowConstantExport: true`);

  * Non-component exports (helpers, types used at runtime, configurations) move to their own files;

  * No explicit `React` import is required - the modern JSX transform resolves it (`react/react-in-jsx-scope: off`); JSX variable usage is still tracked (`react/jsx-uses-react`, `react/jsx-uses-vars`);

  * Enforcement - the rule is supported by the repository [eslint-config-react](https://github.com/rosinfotech/eslint-config-react);

* Benefits:

  * Fast Refresh keeps the component state on edit;

  * Clear file responsibility - components are components;

  * No boilerplate React imports.

* Examples:

  * Case #1:

    * Incorrect:

      ```tsx
      export const API_PATH = "/api/items";
      export function ItemsList() { ... }
      ```

    * Correct:

      ```tsx
      export function ItemsList() { ... }
      // API_PATH lives in its own module
      ```
