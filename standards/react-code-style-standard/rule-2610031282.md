# The Rosinfotech Base Standards

## The React Code Style Standard

### JSX

#### Rule #2610031282

* Context:

  * JSX is code rendered as markup; without a fixed layout the components read as tag soup;

* Description:

  * A multiline JSX tag carries one prop per line (`react/jsx-max-props-per-line`: maximum 1 when multiline); a short tag stays on one line;

  * Tag spacing: no space after the opening bracket, a space before the self-closing slash (`react/jsx-tag-spacing`);

  * The closing tag stays at the level of its opening line (`react/jsx-closing-tag-location`);

  * A multiline JSX expression is wrapped in parentheses on its own lines (`react/jsx-wrap-multilines`);

  * Curly braces inside JSX are consistent between the single- and multiline forms (`react/jsx-curly-newline`);

  * JSX props follow the universal alphabetical sorting ([Rule #2610031256](/standards/common-code-style-standard/rule-2610031256.md), `perfectionist/sort-jsx-props`); `react/jsx-sort-props` stays off - the sorting has one owner;

  * Enforcement - the rule is supported by the repository [eslint-config-react](https://github.com/rosinfotech/eslint-config-react);

* Benefits:

  * Uniform component markup across the codebase;

  * Props diffs stay line-per-change;

  * The sorting owner is single.

* Examples:

  * Case #1:

    * Incorrect:

      ```tsx
      const element = <Button type="primary" disabled
              onClick={handleClick}>Send</Button>;
      ```

    * Correct:

      ```tsx
      const element = (
          <Button
              disabled
              type="primary"
              onClick={handleClick}
          >
              Send
          </Button>
      );
      ```
