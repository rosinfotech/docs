# The Rosinfotech Base Standards

## The React Code Style Standard

### Hooks

#### Rule #2610031280

* Context:

  * Hooks break the rules of function components silently: the failure shows up as lost state, not as an error message;

* Description:

  * Hooks are called only from components and from other hooks, only at the top level - never in conditions, loops or nested functions (`react-hooks/rules-of-hooks`);

  * Dependency arrays are complete: every reactive value used inside the hook is listed (`react-hooks/exhaustive-deps`);

  * Dependency arrays are sorted (`sort-react-dependency-arrays/sort`) - the concrete case of the universal alphabetical sorting ([Rule #2610031256](/standards/common-code-style-standard/rule-2610031256.md));

  * Enforcement - the rule is supported by the repository [eslint-config-react](https://github.com/rosinfotech/eslint-config-react);

* Benefits:

  * Hook call order stays stable across renders;

  * Stale-closure bugs surface at the lint step;

  * Dependency lists are diff-friendly.

* Examples:

  * Case #1:

    * Incorrect:

      ```typescript
      if (visible) {
          const [state, setState] = useState(false);
      }
      useEffect(() => {
          track(id);
      }, []);
      ```

    * Correct:

      ```typescript
      const [state, setState] = useState(false);
      useEffect(() => {
          track(id);
      }, [id]);
      ```
