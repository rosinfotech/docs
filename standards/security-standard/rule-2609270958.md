# The Rosinfotech Base Standards

## The Security Standard

### Sensitive data

#### Rule #2609270958

* Context:

  * Documentation, comments and commit messages easily leak infrastructure details: IPs, ports, hostnames, credentials, tokens, SSH endpoints;

* Description:

  * NEVER write sensitive information into any "reading-oriented" file or any other file tracked by git: README.md, CHANGELOG.md, docs/**, CONTRIBUTING, wikis, `*.md`, comments, commit messages - i.e. anything users read to get familiar with the project: IPs, ports, hostnames, credentials, passwords, tokens, SSH endpoints, internal server details;

  * NEVER write into committed files anything that lives in directories or files covered by gitignore - local repo `.gitignore` OR global gitignore (`~/.config/git/ignore` and equivalents): if git ignores content, duplicating or referencing its data in committed files defeats the ignore;

  * Connection details (IPs, ports, credentials) belong ONLY in secrets files (e.g. `~/.secrets.json`): in committed docs use abstract identifiers only (e.g. a server codename like `orange-zirconium`) - never its address;

* Benefits:

  * No secret leakage through documentation and history;

  * Gitignore keeps its meaning - ignored data stays ignored;

  * Committed docs remain publishable without manual redaction;

* Examples:

  * Case #1:

    * Incorrect:

      ```markdown
      Deploy to orange-zirconium (192.0.2.42, ssh deploy@192.0.2.42 -p 2222)
      ```

    * Correct:

      ```markdown
      Deploy to the `orange-zirconium` server (see `~/.secrets.json` for connection details)
      ```
