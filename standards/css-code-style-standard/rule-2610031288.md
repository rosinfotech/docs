# The Rosinfotech Base Standards

## The CSS Code Style Standard

### Order

#### Rule #2610031288

* Context:

  * A random property order makes declarations unscannable and diffs noisy; a fixed order makes a rule block predictable;

* Description:

  * Properties follow the fixed order of the shared stylelint config (`order/properties-order` from stylelint-order); the full list lives in stylelint-config-standard - the catalog references it and does not restate it;

  * The block structure order (`order/order`):

    * plain declarations first;

    * then the `media` at-rule;

    * then pseudo-elements (`&::before`, `&::after`);

    * then pseudo-classes (`&:hover` and other `&:` modifiers);

    * then BEM modifiers (`&_...`);

    * then nested child rules (`&....` selectors);

  * The property order is the CSS case of the naming sequence [Rule #2103052001](/standards/common-code-style-standard/rule-2103052001.md): from the general (layout, box model) to the specific (visuals, typography);

  * Enforcement - the rule is supported by the repository [stylelint-config-standard](https://github.com/rosinfotech/stylelint-config-standard);

* Benefits:

  * Any declaration is found by its position class;

  * Merges and conflicts are spotted in review;

  * The order is enforced, not remembered.

* Examples:

  * Case #1:

    * Incorrect:

      ```css
      .card {
          color: red;
          position: absolute;
          display: flex;
      }
      ```

    * Correct:

      ```css
      .card {
          position: absolute;
          display: flex;
          color: red;
      }
      ```
