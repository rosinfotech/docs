# The Rosinfotech Base Standards

## The Git Code Project Standard

### EditorConfig

#### Rule #2610031936

* Context:

  * Without a shared editor configuration every editor formats its own way - tabs against spaces, encodings and line endings drift per contributor;

* Description:

  * Every git project carries `.editorconfig` in its root - copied as-is from the asset [.editorconfig](/standards/git-code-project-standard/assets/.editorconfig) of this standard;

  * The shared block fixes:

    * UTF-8 charset;

    * LF line endings;

    * 4-space indentation (tabs off);

    * the final newline at the file end;

    * the line length hint of 120;

    * `*.md` uses a 2-space indentation - the markdown exception of the code style standards;

  * The file is copied as-is: project-specific file types append their own sections below the shared blocks - the shared blocks themselves are never edited per project;

  * Enforcement - the rule is supported by this repository (the asset) and by [rosinfotech/makefile](https://github.com/rosinfotech/makefile): the vendoring procedure ([Rule #2610031938](/standards/git-code-project-standard/rule-2610031938.md)) scaffolds the same file into a fresh project;

* Benefits:

  * One formatting baseline for every editor and IDE;

  * The editor settings match the code style standards (4 spaces, LF, the markdown exception);

  * Fresh projects get the file automatically via the vendoring.

* Examples:

  * Case #1:

    * Incorrect:

      * a project where every committer's editor fights the formatter over tabs and encodings;

    * Correct:

      * the root carries the `.editorconfig` copied from the asset - the editors apply the shared baseline from the first open.
